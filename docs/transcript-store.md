# Общее хранилище транскрипций

Единственный источник формата для Folder-video, Окошка и YouTube Radar. Менять формат только здесь и синхронно во всех приложениях. Эталонная логика — `src/shared/transcript-store-core.js`, эталонные файлы — `tests/fixtures/transcript-store/`.

## Папка

- Настройка «Папка транскрипций» в каждом приложении; по умолчанию `Documents\Transcripts`.
- Папка плоская, подпапок нет. Все файлы одного источника имеют общее имя (stem).
- Папка окружения распознавания (`transcribe.dll`, модели) — отдельная настройка, по умолчанию `%LOCALAPPDATA%\transcribe-shared`.

## Имя файлов (stem)

| Источник | Stem |
| --- | --- |
| Локальное видео | `<имя без расширения>__<первые 12 символов SHA-256 полного пути>`; в имени `<>:"/\|?*` заменяются на `_`, длина до 120 |
| Ролик YouTube | `yt-<id>` (id — ровно 11 символов `[\w-]`) |

Схему имён менять нельзя: по ней находятся уже созданные файлы.

## Файлы

| Файл | Содержимое |
| --- | --- |
| `<stem>.srt` | Транскрипция (фразы с таймкодами) |
| `<stem>.txt` | Тот же текст без таймкодов |
| `<stem>.json` | Манифест (ниже) |
| `<stem>.ru.srt`, `<stem>.ru.txt` | Русский перевод (создаёт YouTube Radar) |
| `<stem>.summary.json` | Сводка ИИ |
| `<stem>.notes.md` | Заметки с таймкодами |
| `<stem>.lock` | Признак идущей транскрибации |

Запись всегда атомарная: во временный файл `<файл>.<pid>.tmp`, затем `rename`.

## Манифест

Версия 2:

```json
{
  "version": 2,
  "source": { "kind": "file", "path": "D:\\v\\a.mp4", "size": 1000, "mtimeMs": 1700000000000, "sha256": "необязательно" },
  "transcript": { "model": "parakeet-tdt-0.6b-v3-Q8_0.gguf", "engine": "parakeet-tdt", "language": "необязательно", "createdAt": "ISO", "createdBy": "folder-video|okoshko|youtube-radar" },
  "translations": { "ru": { "createdAt": "ISO", "createdBy": "youtube-radar" } }
}
```

Для ролика `source` — `{ "kind": "youtube", "id", "url", "title" }`. Манифест версии 1 (`filePath`, `size`, `mtimeMs`, `modelPath`) читается как раньше; версия 2 пишется при следующей записи. `sha256` заполняется лениво, только если хэш уже посчитан.

## Актуальность

- Транскрипция локального видео устарела, если изменились путь, размер или mtime. Модель и приложение не сравниваются, перегенерация — вручную.
- У ролика YouTube источник не меняется: транскрипция актуальна, пока файл существует.
- Сводка устарела только при изменении текста транскрипции (`transcriptHash` — SHA-256 содержимого `.srt`). Модель ИИ записывается, но не сравнивается.

## Сводка (`.summary.json`)

```json
{ "version": 1, "filePath": "…", "size": 0, "mtimeMs": 0, "transcriptHash": "…", "model": "провайдер/модель или имя модели", "summary": { "overview": "…", "topics": [ { "title": "…", "description": "…", "start": 12.5 } ] } }
```

У ролика YouTube `filePath/size/mtimeMs` отсутствуют. Запрос к ИИ, нарезка на пакеты и нормализация — как в `src/main/summary-core.js`.

## Заметки (`.notes.md`)

Блоки, разделённые строкой `---`; первая строка блока — `[м:сс]` или `[ч:мм:сс]`. Разбор — `src/shared/notes-core.js`. До 1 МБ; пустой текст удаляет файл.

## Lock

`<stem>.lock`: `{ "app": "okoshko", "pid": 4242, "startedAt": "ISO" }`. Пока lock живой, другие приложения не запускают транскрибацию этого источника и показывают «Транскрибация уже идёт в <приложение>». Lock устарел, если процесса `pid` нет или прошло более 6 часов; устаревший lock удаляется.

## Привязка локального файла к YouTube

Если у локального видео есть ссылка YouTube и своей транскрипции нет, приложения могут показать `yt-<id>.*` только для чтения, с пометкой «транскрипция ролика YouTube». Автоматического копирования нет.

## Распознавание

Все приложения вызывают `transcribe.dll` через koffi в отдельном процессе; звук берётся из системного `ffmpeg` (`PATH`) потоком f32le 16 кГц кусками по 15 с. Слова собираются во фразы (`wordsToPhrases`): разрыв при паузе более 1 с или длине более 30 с, закрытие на `. ! ? …`.
